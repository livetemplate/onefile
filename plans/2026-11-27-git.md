# Plan: a git onefile app, with live status, branches and log, and buttons to stage, commit and switch

State — Done: plan (onefile#20), Phases 1 and 2 (tinkerdown#393, #394, released in v0.11.0), Phase 3 (onefile#21), the check from GitHub, R2, A4 and A6. Next: release the fsnotify fix (tinkerdown#397) as 0.11.1.

## Context

The next app is `git`, third on the [roadmap](../ROADMAP.md) and the top one not built. One page shows the working tree's changed files, the branches and the log. git runs again every 2 seconds and after each click, or, with `--watch-dir`, when a file in the repo changes, so all three stay current. Buttons stage and unstage a file, switch branch, and commit with a typed message, and clicking a file shows its diff. It covers the everyday loop people open lazygit for, not every git command.

One rule from review shapes the design: tinkerdown never does the tool's job (user, 2026-11-23). So git prints every list, and tinkerdown learns only general features, listed below.

The audit (2026-11-27, git 2.53.0, Linux) settled these facts:
- `git status --porcelain` quotes a path with a space, a `"` or a non-ASCII byte (`"sp ace.txt"`, `"caf\303\251.txt"`), and writes a rename as `a.txt -> b.txt`. `core.quotePath=false` unquotes only the non-ASCII one. A quoted path can't be passed back to git.
- With `-z --no-renames`, each entry is `XY PATH`, with the path as it is, and a rename is a `D` entry and an `A` entry. `tr '\000' '\n'` turns the entries into lines.
- `--` ends options but not pathspec magic. With `GIT_LITERAL_PATHSPECS=1`, `git add -- ':/'` and `git add -- '*'` fail with "did not match any files", where without it they stage everything.
- `git for-each-ref --format` and `git log --format` write a tab as `%09` and `%x09`. Neither prints JSON. A subject keeps `"` and `<b>` as written.
- `git switch -- feat` works, and `git switch HEAD~0` refuses: "a branch is expected".
- In a repo with no commits, `git log`, `git diff HEAD` and `git restore --staged` fail, while `git reset -q -- PATH` and `git diff --cached` work.
- `git diff --no-index -- /dev/null PATH` shows a new file's content, and exits 1 because the two differ.

tinkerdown can't yet:
- Rerun a command that prints a list, on a timer or when files change, and replace the rows with its output. A keyed merge removes a row only on a `drop` match, so a file you commit would stay listed (Phase 1).
- Split a plain line into fields. git prints tab-separated text, and tinkerdown parses JSON and logfmt (Phase 1).
- Check an action's values against a page's rows ([tinkerdown#362](https://github.com/livetemplate/tinkerdown/issues/362)), so a hand-made message could stage any path (Phase 2).
- Take typed text with a click. Every param needs `in`, so a commit message can't reach an `on:` merge. An `--action` can take it, but it stops at 30 s, which a pre-commit hook that runs tests can pass (Phase 2).

## Product

| User journey | What they see | Built on |
|---|---|---|
| See what changed | one row per file: its staged and unstaged state, and its path | `--source status=`, a merge with `every` and `pattern` (Phase 1) |
| Stage or unstage a file | Stage or Unstage on the row, whichever applies; the row moves at once | `--action stage=` and `unstage=`, values checked (Phase 2); a click reruns the lists (Phase 1) |
| Read a file's diff | click the path; the pane shows added and removed lines, kept current | a `params` merge with `every`, rows linking to `?path=` |
| Commit | a message box and Commit; the pane shows the hooks' output and git's summary, then the file list empties | an `on: commit` merge with a typed `message` (Phase 2) |
| See branches | each branch, the current one marked, ahead or behind its upstream | `--source branches=` |
| Switch branch | Switch on a row; when git refuses, such as for changes in the way, its message shows | `--action switch=` |
| Read the log | the last 100 commits: short hash, date, author, branch names and subject | `--source log=` |

## What the code looks like

The serve command, as the README will publish it. Users copy it, so it's the app's contract. The two variables before `tinkerdown` reach every command:

```sh
GIT_LITERAL_PATHSPECS=1 GIT_OPTIONAL_LOCKS=0 tinkerdown serve --allow-exec github.com/livetemplate/onefile/git \
  --source 'status=git status -z --no-renames --untracked-files=all | tr "\000" "\n"' \
  --source 'branches=git for-each-ref --format="%(HEAD)%09%(refname:short)%09%(upstream:track,nobracket)%09%(committerdate:format:%m-%d)%09%(contents:subject)" refs/heads' \
  --source 'log=git log -n 100 --date=format:%m-%d --format="%H%x09%h%x09%cd%x09%an%x09%D%x09%s"' \
  --source 'diff=if [ -n "$(git ls-files -o --exclude-standard -- "$TD_path")" ]; then git diff --no-index -- /dev/null "$TD_path"; [ $? = 1 ]; else git diff --cached -- "$TD_path"; git diff -- "$TD_path"; fi' \
  --source 'commit=git commit -m "$TD_message"' \
  --action 'stage=git add -- "$TD_path"' \
  --action 'unstage=git reset -q -- "$TD_path"' \
  --action 'switch=git switch -- "$TD_branch"'
```

Adding `--watch-dir .` swaps the 2 s timer for file events in the folder it names.

The page's sources and actions. Each merge is named apart from its input, because a `--source` flag replaces a page source of the same name. The audits can change the details:

```yaml
sources:
  files:     {type: merge, inputs: [status], every: 2s, key: [fields.path], pattern: '^(?P<x>.)(?P<y>.) (?P<path>.+)$'}
  refs:      {type: merge, inputs: [branches], every: 2s, key: [fields.name], pattern: '…'}
  commits:   {type: merge, inputs: [log], every: 2s, key: [fields.hash], pattern: '…'}
  filediff:  {type: merge, inputs: [diff], every: 2s, pattern: '^(?P<mark>[-+@]?)', params: {path: {in: files.fields.path}}}
  committed: {type: merge, inputs: [commit], on: commit, params: {message: {typed: true}}}
actions:
  stage:   {values: {path: {in: files.fields.path}}}
  unstage: {values: {path: {in: files.fields.path}}}
  switch:  {values: {branch: {in: refs.fields.name}}}
```

A file row: `<li data-key="{{.key}}" data-x="{{.fields.x}}" data-y="{{.fields.y}}">`, a link to `?path={{.fields.path}}`, and `<button name="stage" data-path="{{.fields.path}}">`. CSS on `data-x` and `data-y` hides the button that doesn't apply, since a per-row `{{if}}` ends row-by-row updates. The commit box is `<form><input name="message" maxlength="256"><button name="commit">`, disabled while `.Running`.

Phase 1 adds two merge options and a flag:
- `every: 2s` reruns each input 2 s after it exits, while a page shows the merge, and replaces the input's rows with each run's.
- `tinkerdown serve --watch-dir DIR` reruns each `every` merge when a file under DIR changes, in place of the timer. `--watch` already turns on hot reload.
- `pattern: REGEX` gives a line that matches the regex's named groups as its `fields`.

Phase 2 adds two kinds of value:
- `actions: {NAME: {values: {V: {in: MERGE.PATH}}}}` in a page runs the `--action NAME=` command only when each value is in a row of MERGE, as tinkerdown#362 proposes. A page from a URL may hold actions that set only `values`.
- A param `{typed: true}` on an `on:` merge takes the click's value from a form field, with no `in`.

## Decisions

- git runs again every 2 s and after each click. `--watch-dir .` swaps the timer for file events (user, 2026-11-27).
  alternative: always watch files
  because: a watch misses changes on network file systems, and on macOS fsnotify's kqueue opens one file per watched file, so a big repo can hit the limit. The timer works everywhere
- The person running `tinkerdown serve` names the watched folder, not the page.
  alternative: a `watch: [PATHS]` merge option
  because: a page from a URL then can't watch outside the folder it runs in, and needs no path checks
- A watch adds every folder under DIR, dot folders such as `.git` included, and adds a new folder when one appears.
  alternative: reuse `internal/server/watcher.go`
  because: it skips dot folders, reacts only to `.md` and included files, and runs only when the server watches its own pages
- A run starts 200 ms after the last event, one at a time, with one more queued at most.
  alternative: none considered
  because: a commit writes dozens of files under `.git/objects`
- When a click's command ends, every running `every` input in the server runs at once, whether the command failed or not. That covers any custom action and an `on:` merge's run.
  alternative: wait for the next 2 s run
  because: a 2 s gap after Stage looks like a missed click
- Status comes from `git status -z --no-renames --untracked-files=all`, with `tr` turning NULs into newlines.
  alternative: plain `--porcelain`, or awk turning it into JSON
  because: plain output quotes paths with spaces, which then can't be passed back to git, and awk would make the command several times longer. `--untracked-files=all` lists files, not folders, so every row has a diff
- A rename shows as a deleted file and an added file.
  alternative: `-z` with renames
  because: a rename's old path comes as its own entry, which `pattern` would misread as `XY PATH`
- `GIT_LITERAL_PATHSPECS=1` and `GIT_OPTIONAL_LOCKS=0` go before `tinkerdown serve`, so every command gets them.
  alternative: `--literal-pathspecs` and `--no-optional-locks` on each command
  because: one place, shorter commands, and a command the user adds later gets them too
- Unstage is `git reset -q -- PATH`.
  alternative: `git restore --staged`
  because: `restore` fails in a repo with no commits yet
- The diff pane shows staged changes, then unstaged ones. For a new file, it shows the file's content.
  alternative: `git diff HEAD`
  because: it fails before the first commit
- Commit runs through an `on: commit` merge, not an `--action`.
  alternative: `--action 'commit=git commit -m "$TD_message"'`
  because: an action stops at 30 s and shows output only when it fails. A pre-commit hook that runs tests can take longer, and its output is what you need when it fails
- The commit runs the repo's hooks. The README never passes `--no-verify`.
  alternative: none considered
- A message is one line, up to 256 bytes.
  alternative: several lines up to 128 KiB, as a row's private values allow
  because: the usual value rules keep `"$TD_message"` safe as an argument, and a commit from a page is usually a subject line
- The page leaves out push, pull, discard, stash, amend, merge and staging part of a file.
  alternative: none considered
  because: discard loses work with no undo, and push and pull reach a remote and can ask for a password. The roadmap row asks for status, branches, log, stage, commit and switch
- Dates are absolute and formatted by git (`--date=format:%m-%d`), such as `11-27`.
  alternative: relative dates (`%cr`), such as "2 hours ago"
  because: with `--watch-dir`, no timer runs, so a relative date would never change. tinkerdown has no date function
- The e2e test runs real git on a repo it makes in a temp directory.
  alternative: a fake `git` first on `PATH`, as db's fake `sqlite3`
  because: git needs no network or service, and a fake would hide the quoting and locking facts above
- `every` is a merge option, not a stream one.
  alternative: `every` on the stream source
  because: a `--source` flag can't set a stream's options, and the merge is the part of the page that knows how its list is printed
- A run's rows replace the input's rows when the run exits.
  alternative: a marker line that the command prints after each list, in a `while` loop
  because: the command stays one git call, and a click can start a run at once
- On an `every` merge, rows show in the latest run's order unless `sort` is set.
  alternative: first-seen order, as other keyed merges have
  because: a new commit then shows at the top of the log, where git prints it
- A run that prints the same lines as the last one changes nothing.
  alternative: none considered
  because: otherwise each 2 s run would send every row again
- A run that fails keeps the last rows, and sets the block's `.Error` to its stderr and exit status until a run succeeds. Only stdout becomes rows.
  alternative: replace the rows with the failed run's output
  because: a brief failure, such as a lock held by another git, shouldn't empty the page
- `every` inputs and their watches stop 30 s after the last page showing them closes, as `params` inputs do (`MergeIdle`, renamed from `MergeParamIdle`).
  alternative: 5 minutes, as other inputs do
  because: a list keeps no history worth holding, and git would keep running for nothing
- `pattern` takes Go's regex syntax with named groups. A matching line's groups replace the fields that JSON or logfmt parsing found, and a line that doesn't match keeps them.
  alternative: a `columns` list for tab-separated lines
  because: `git status` isn't tab-separated, and other tools' plain text (`ps`, `du`, `lsof`) needs a regex too. Go's regexp runs in linear time, so a pattern can't hang the server
- A page from a URL may set `every` down to 1 s, and a `pattern` up to 1 KiB.
  alternative: none considered
- An action's values are checked in the page, as tinkerdown#362 proposes.
  alternative: run stage, unstage and switch through `on:` merges, which have `in` already
  because: a second click stops an `on:` run, which could kill `git add` midway and leave `index.lock`. An action runs to its end
- A typed param works only on an `on:` merge.
  alternative: also on a `params` merge, from the URL
  because: an `on:` merge ignores the URL, so a link can't send one. A hand-made click can send only what the box could

## Security

- **What runs:** every 2 s, or with `--watch-dir` when a file changes, while a page is open, `git status`, `git for-each-ref`, `git log` and `git diff` read the repo. With `GIT_OPTIONAL_LOCKS=0`, none of them writes the index. Clicks run `git add`, `git reset -q` (which keeps your edits), `git switch` (which refuses to overwrite changes) and `git commit` (which runs the repo's hooks). None deletes work or reaches a remote. A watch only learns which files changed, in a folder the person running tinkerdown named.
- **Values from the browser:** `path` goes to stage, unstage and the diff, and must be in `files.fields.path`. `branch` goes to switch, and must be in `refs.fields.name`. `message` goes to commit and passes the value rules only. Each is quoted and placed after `--`, and paths are literal.
- **Hand-made messages and URLs:** a message can stage or unstage a listed file, switch to a listed branch, or commit with any one-line message, which is what the buttons do. A URL can open a listed file's diff and nothing else.
- **Secrets:** the diff pane shows a file's content, so a new `.env` that `.gitignore` misses shows in full. Author names show and emails don't.
- **Untrusted text:** paths, branch names, subjects, author names, diff lines and hook output, all rendered by Go's `html/template`.
- **The README warns:** anyone who can open the page can stage and commit in the repo it runs in. The diff pane shows new files' contents. Commit runs the repo's hooks.

## Constraints

- A merge without `every` or `pattern`, an action without `values`, and `serve` without `--watch-dir` work as today.
- A rerun never takes a lock that makes the user's own git commands fail (A3).

## Contract

Rows, from each merge's `pattern`:
- `files`: `x` and `y`, then `path`. `x` and `y` are each one of ` `, `M`, `T`, `A`, `D`, `U` and `?`. Renames are off, so `R` and `C` don't occur.
- `refs`: `head` (`*` or ` `), `name`, `track` (`ahead N`, `behind N`, `ahead N, behind M`, `gone` or empty), `when` and `subject`.
- `commits`: `hash`, `short`, `when`, `author`, `refs` (as `%D` prints them, such as `HEAD -> main, origin/main`) and `subject`.
- `filediff`: `mark`, one of `+`, `-`, `@` or empty.

Clicks: `stage` and `unstage` with `data-path`, `switch` with `data-branch`, and `commit` with the form field `message`. A file row links to `?path=`.

Defaults: `every` 2 s on this page, and at least 1 s on any page from a URL. With `--watch-dir`, a run starts 200 ms after the last file event. Inputs and watches stop 30 s after the last page closes. The log shows 100 commits. A pattern holds up to 1 KiB, and a typed value up to 256 bytes.
